# Database Standards

Status: Approved ✅

---

# Purpose

Defines the database conventions used throughout LeadFlow AI.

Every entity, table, relation, enum, index and migration must follow these standards.

These rules ensure consistency, maintainability and scalability.

---

# Primary Keys

- UUID Version 7
- Generated by the application
- Never auto increment

Example

id UUID

TIMESTAMPTZ

ISO-8601

UTC

---

# Soft Delete

Every business table should support soft delete unless there is a strong reason not to.

Standard Column

deleted_at

Hard delete is reserved for:

- Temporary tokens
- Cache
- Queue data
- Logs (based on retention policy)

# Unique Constraints

Use composite unique constraints whenever required.

Examples

UNIQUE(organization_id, user_id)

---

# File References

Never store file URLs.

Always reference

file_id

The Files module is responsible for generating URLs.

---

# Identity

Always use

identifier_type

identifier_value

Never create separate email or phone concepts for identity-based workflows.

Examples

Verification Codes

Invitations

Authentication

---

# Date Storage

Never store local time.

Always store UTC.

Frontend is responsible for local formatting.

---

# Permission Model

Permissions are global.

Permissions are immutable.

Permissions are assigned only through Roles.

Users never receive permissions directly.

---

# Membership Model

Organization access is always determined by Membership.

Never attach organization permissions directly to users.

---

# Organization Ownership

Ownership is determined through Role assignment.

There is no owner_id column.

# Migration Rules

- Never edit executed migrations.
- Every schema change requires a new migration.
- Never change production data manually.
- Use seed files for default data.

---

# Performance

- Avoid N+1 queries.
- Index every foreign key.
- Load relations only when required.
- Use pagination for list endpoints.

---

# Security

Never store

- Plain passwords
- Plain refresh tokens
- Plain verification tokens
- Plain invitation tokens

Always store hashes.
